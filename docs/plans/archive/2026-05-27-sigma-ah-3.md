# Σ.AH.3 — Build-vs-probe side-swap optimizer rule (CLOSED 2026-05-27)

**Status:** **CLOSED 2026-05-27.** See [docs/PHASE_SIGMA_AH_3_DESIGN.md](../../PHASE_SIGMA_AH_3_DESIGN.md) § 4 + § 4a for spike numbers, dig-in evidence, and decision. Memory: `[[sigma-ah-3-arc-closed]]`.

**TL;DR:** Phase 0 spike (Story 1.2) found the mechanism already shipped as opt-in `EMAT_REORDER=1` from the archived Σ.T arc (commit `1a14007`, 2026-05-25). Re-benching at SF=10 confirmed the Σ.T finding: estimator can't model nation-fanouts or string-LIKE selectivity, picks bad join orders. Q07 regresses +30%, Q09 regresses +32%, only Q10 wins (-9%).

User pushed back on a quick rejection: *"Could this be exposing a different inefficiency that was previously hidden in Q7 and Q9?"* That triggered a dig-in via Story 2a (L9 selectivity-threshold gate) — implementation correct, tested, but the bench ruled out the "L9 over-fire causes reorder regression" hypothesis. The +42 ms Q07 reorder regression comes from the join order itself; only ~5 ms came from L9 over-firing.

## Banked outputs

1. **`EnableRuntimeBloomSidebandRule::max_expected_keys_per_partition`** field + env `EMAT_L9_MAX_EXPECTED_KEYS=N`, default 0 (disabled). 2 unit tests. Defensive infra for future shapes that bypass `require_filtered_build`.
2. **Q10 cust⋈orders sliver** (-25 ms wall under EMAT_REORDER) migrated to Σ.AH.X salvage arc as Lever G "shape-detect EMAT_REORDER for cust⋈orders pattern."
3. **Decision criterion for future L9-shape levers**: `require_filtered_build` already handles the FK-bloom net-negative pattern correctly. Absolute build size isn't a reliable rejection signal; the right model is "build unfiltered = bad."
